# Stream Notify 1.0 — техническое задание

**Документ:** ТЗ-001 • **Версия:** 1.0 • **Дата:** 24 октября 2026 года • **Статус:** утверждённая функциональная концепция, готовая к реализации и технической приёмке.

## 1. Назначение и принципы продукта

Stream Notify — лёгкий **нативный плагин OBS Studio для Windows**, который после успешного старта трансляции выдерживает заданную задержку и публикует одно объявление с **постоянными ссылками** на YouTube и Twitch в Telegram и/или Discord. Плагин работает внутри OBS; дополнительное приложение, Python, сервер, регистрация в Stream Notify и YouTube API не требуются.

Ключевые принципы: **установил → настроил один раз → запускаешь OBS → стримишь**; полная локализация RU/EN; минимальная нагрузка; прозрачная индикация результата; безопасность секретов; запрет нежелательного дублирования рассылки.

**Вне функционала версии 1.0:** поиск ID живого эфира, запросы к YouTube/Twitch, получение названия трансляции, управление запуском OBS/стрима, OBS WebSocket, собственный облачный сервер, многопользовательский кабинет, подписки, Android/macOS/Linux, публикация в других сетях.

## 2. Платформа и поставка

- Целевая платформа: Windows 10/11, x64, стандартная настольная сборка OBS Studio 30.0 и новее. Перед релизом обязательно проверить совместимость с выбранными поддерживаемыми ветками OBS; совместимость со всеми будущими версиями не обещать заранее.
- Реализация: C++17 или новее, нативный модуль OBS (`.dll`) + виджет на Qt из стека OBS, без браузерного дока и без отдельного постоянно работающего процесса.
- Встраивание: OBS Frontend API; уникальный dock ID `stream-notify-dock`; подписка на события начала/остановки трансляции; сетевые операции неблокирующие и не на главном потоке UI.
- Поставка: один подписываемый при возможности установщик `.exe` для Windows с деинсталлятором. Установщик проверяет установленную OBS и разрядность, не требует Python, не устанавливает фоновые службы.
- Первое открытие OBS после установки: панель **автоматически создаётся и показывается**, предпочтительно справа. После первого запуска сохраняются выбранные пользователем видимость, размеры и положение; намеренно скрытую панель нельзя принудительно открывать каждый раз.
- При выключенном или закрытом доке рабочая логика уведомлений продолжает действовать. Не должно быть зависимости отправки от видимости UI.
- Если OBS уже запущена, установка предлагает закрыть её; принудительное завершение OBS недопустимо.

## 3. Пользовательский сценарий (основной)

1. Пользователь устанавливает плагин, открывает OBS — появляется док-панель Stream Notify со вкладками «Основное» и «Настройки».
2. На вкладке настроек пользователь активирует Telegram и/или Discord **независимо**, вводит реквизиты, ссылки на YouTube/Twitch, текст, задержку и язык. Все изменения сохраняются автоматически.
3. До стрима панель показывает обычный интерфейс и состояние готовности. Проверки сайтов, таймеры и сетевые запросы в ожидании **не выполняются**.
4. Пользователь нажимает в OBS «Начать трансляцию». Плагин ждёт события **успешного старта вещания** `OBS_FRONTEND_EVENT_STREAMING_STARTED` и лишь затем запускает обратный отсчёт 60/90/120 секунд.
5. Вся площадь **содержимого** док-панели (кроме системной рамки/заголовка OBS) переключается на крупный экран таймера. Есть кнопка «Отменить отправку», перечень включённых адресатов и время до отправки.
6. По завершении отсчёта при активном эфире плагин отправляет сообщение только во включённые и корректно настроенные мессенджеры, каждый — не более одного раза за текущий эфир (кроме контролируемых попыток после достоверного отказа).
7. После завершения обработки отображается полноразмерный экран результатов: зелёный — полный успех, янтарный — частичный, красный — ни одна включённая доставка не подтверждена. По каждому каналу отдельный статус.
8. Итоговый экран остаётся на **30/45/60 секунд** (по умолчанию 45), после чего возвращается основная панель. Последний результат сохраняется и доступен на «Основном» и в локальном журнале.
9. До следующего нового стрима плагин не выполняет активных действий, кроме обработки событий OBS и действий пользователя.

## 4. Навигация и состав экранов

Основные вкладки: **«Основное» / «Настройки»**. В «Настройках» — подстраницы **«Подключения» / «Сообщение» / «Интерфейс»**. Навигация и оформление должны соответствовать утверждённым тёмным прототипам: тёмно-синий фон, графичные карточки, умеренные зелёные/голубые акценты, понятная типографика и компактное отображение в узкой колонке OBS.

### 4.1. «Основное» (до эфира и после завершения цикла)

- Название и версия Stream Notify; индикатор общего режима: «Активен», «Выключен», «Требуется настройка».
- Главный переключатель «Автоуведомления» (ВКЛ/ВЫКЛ).
- Текущий статус OBS: не в эфире / идёт эфир / рассылка отменена / результат отправки.
- Секция Telegram и Discord: значок, включён/выключен, не настроен/готов/отправлено/ошибка, **отдельная кнопка «Тест»** напротив каждого.
- Секция постоянных ссылок YouTube/Twitch, кнопки копирования; на «Основном» поля допускается показывать только для чтения, редактировать в «Подключениях».
- Блок «Последнее уведомление»: время, результат **каждого** включённого канала, понятное объяснение ошибки при наличии.
- **Нет общей кнопки теста внизу**: тестируются только Telegram и Discord по отдельности.
- При открытии настроек не допускается потеря несохранённого ввода: см. §9.

### 4.2. «Настройки → Подключения»

- Telegram: независимый переключатель «Отправлять в Telegram»; поле токена бота (маска + кнопка «показать»); поле Chat ID / `@username` публичного канала; кнопка «Тест»; ссылка «Как настроить».
- Discord: независимый переключатель «Отправлять в Discord»; поле Webhook URL (маска + временный показ); кнопка «Тест»; ссылка «Как создать вебхук».
- YouTube URL и Twitch URL: текстовые поля с проверкой URL и возможностью очистить; постоянная YouTube-ссылка вида `https://www.youtube.com/@CHANNEL/live`, Twitch — `https://www.twitch.tv/CHANNEL`. Адреса редактируются каждым пользователем индивидуально.
- Переключатели Telegram и Discord работают независимо: выключение одного **не удаляет** его токен/вебхук и не влияет на другой. Статус «Отключён» не является ошибкой.
- Статус «Готов» означает: обязательные поля валидны локально; статус «Подключение проверено» — только после успешного запроса теста. Не заявлять о сетевой доступности без тестирования.
- Отсутствие хотя бы одного включённого и настроенного адресата запрещает автоотправку и показывает пояснение; пустое поле отключённого сервиса не мешает другому.

### 4.3. «Настройки → Сообщение»

- Редактор общего текстового шаблона с многострочным вводом и счётчиком символов.
- Переменные версии 1.0: `{youtube}` и `{twitch}`; кнопки их вставки; интерактивный предпросмотр фактически отправляемого текста.
- **`{title}` в версии 1.0 не поддерживается**: название YouTube/Twitch автоматически не получается, поскольку нет обращений к их API. Неизвестные переменные должны быть подсвечены и вызывать предупреждение до рассылки.
- Если URL не задан, соответствующая строка по умолчанию убирается, а не остаётся пустая ссылка; обязательна хотя бы одна корректная ссылка, если шаблон использует переменные.
- По умолчанию текст:

  `🔴 НАЧАЛСЯ СТРИМ!\n\nСмотрите трансляцию:\n▶️ YouTube: {youtube}\n🎮 Twitch: {twitch}`

- Отложенная отправка **60 / 90 / 120 секунд**, по умолчанию 60; меньше 60 невозможно выбрать даже из конфигурационного файла (валидация при чтении).
- Стандартное поведение «одно объявление на эфир» — обязательная логика, а не отключаемая опция.
- Повторы при подтверждённой сетевой ошибке разрешены с ограничениями (§7). Всплывающие уведомления OBS — переключатель.
- Предпросмотр не создаёт сетевых запросов и не отправляет сообщение. Лимит до 1 000 символов в поле редактора (для безопасной совместимости; Discord допускает более длинные сообщения, но интерфейс 1.0 ограничивает их сам).

### 4.4. «Настройки → Интерфейс»

- Язык: «Автоматически / Русский / English»; при первом запуске определяется язык OBS, иначе английский; ручной выбор имеет приоритет и сохраняется.
- Полный перевод: навигация, кнопки, тесты, таймер, успех/частичный успех/ошибки, журнал, подсказки и мастер первого подключения.
- Язык **отправляемого текста не меняется** при смене языка UI: шаблон остаётся пользовательским.
- Длительность итогового экрана: 30 / 45 / 60 секунд, по умолчанию 45.
- Компактный режим дока (опциональный переключатель), индикатор в заголовке, всплывающие сообщения OBS.
- Локальный журнал: дата/время, старт, отмена, попытки и итог отдельно по каналам; «Очистить журнал»; журнал ограничен, не хранит секреты.
- Справка по токену Telegram и Discord Webhook, версия плагина, сведения о лицензии.

## 5. Полноэкранные состояния док-панели

| Состояние | Вид и содержимое | Условие перехода |
|---|---|---|
| `IDLE` | Полный обычный интерфейс | OBS не вещает либо цикл закончен |
| `COUNTDOWN` | Крупные `MM:SS`, круговой прогресс, адресаты, кнопка отмены | Событие успешного старта и активная автоотправка |
| `SENDING` | «Отправка уведомлений…», индикатор по каждому каналу | Истекла задержка; эфир ещё активен |
| `SUCCESS` | **Зелёный фон**, большая белая галочка, «Уведомления отправлены», Telegram ✓ / Discord ✓ по включённым | Все включённые отправки подтверждены |
| `PARTIAL` | Янтарный/нейтральный фон, «Отправлено частично», отдельные ✓ / ✕ / ? | Успех хотя бы в одном канале, неуспех или неопределённость в другом |
| `FAILED` | Красно-тёмный фон, «Не удалось отправить», отдельные ошибки | Ни одна включённая отправка не подтверждена |
| `CANCELLED` | Нейтральное уведомление «Отправка отменена» | Ручная отмена или остановка до отправки |

- Кнопка **«Отменить отправку»** есть только на экране обратного отсчёта. Она запрещает отправку **для текущего эфира**, но **не выключает** глобальный переключатель и не меняет постоянные настройки.
- Если эфир остановлен до отправки, таймер удаляется и отправка отменяется. При отмене экран кратко показывает подтверждение (3 секунды), затем открывается «Основное».
- На таймере видны статусы включённых каналов. Отключённые не выводятся как ошибки; допустима подпись «Discord отключён».
- Зелёный экран допустим **только если все включённые каналы подтверждены**. Если один отключён, успех второго считается общим успехом (с подписью «Второй канал отключён»).
- `SUCCESS`, `PARTIAL`, `FAILED`: показ 30/45/60 секунд; отдельные результаты всегда видны; затем автоматический возврат на «Основное».
- Таймер обратного отсчёта обновляет изображение не чаще 1 раза в секунду; «декоративная» непрерывная анимация и интенсивные эффекты запрещены.

## 6. Работа с OBS и определение нового эфира

- Основной стартовый сигнал: `OBS_FRONTEND_EVENT_STREAMING_STARTED`, а не нажатие кнопки, поскольку соединение и запуск могут завершиться ошибкой. События `STREAMING_STARTING`, `STREAMING_STOPPING`, `STREAMING_STOPPED` используются для безопасности и отмены.
- Таймер запускается **один раз за сеанс трансляции**. Переподключение к серверу, смена сцены, изменение профиля OBS, закрытие/открытие дока и повторная сигнализация не должны вызывать повторную рассылку.
- Новый сеанс формируется только после подтверждённого завершения предыдущего эфира и нового успешного старта. Для пограничных случаев нужна проверка наблюдаемого состояния OBS + тесты на реальном reconnect; не считать любой сетевой разрыв новым эфиром.
- Если OBS или плагин запущены **посреди уже активного эфира**, автоматически **не отправлять** уведомления задним числом: показывать «Эфир уже идёт — автоотправка пропущена». Это предотвращает дубль после перезапуска программы.
- При выключенном общем переключателе или обоих адресатах — таймер не запускается; на главной панели понятный статус.
- Если настройки меняют во время обратного отсчёта, для текущего сеанса берётся зафиксированный при старте снимок настроек (адресаты, шаблон, ссылки, задержка). Новые изменения применяются к следующему эфиру. Пользователю сообщается об этом в подсказке.
- Тестовые сообщения не изменяют состояние текущего эфира и не снимают блокировку повторной автоотправки.

## 7. Отправка Telegram и Discord, ошибки, отсутствие дублей

- Telegram: HTTPS POST к `sendMessage` официального Bot API; `chat_id` — числовой ID или `@username` публичного канала. Успех — валидный ответ API `ok=true` и идентификатор отправленного сообщения.
- Discord: HTTPS POST через Incoming Webhook с параметром `wait=true`; успех — подтверждённое сохранённое сообщение/его ID, а не только факт запуска HTTP-запроса. В Discord по умолчанию `allowed_mentions: {parse: []}` — без неожиданного `@everyone`.
- Каждый получатель обрабатывается **независимо**. Отказ Discord не вызывает повтор Telegram после подтверждённого успеха.
- Перед отправкой проверяются: трансляция активна, сеанс не отменён, есть хотя бы один валидный адресат, шаблон корректен.
- Сетевые таймауты на запрос: разумный ограниченный таймаут (ориентир 8–10 секунд); интерфейс и кодер OBS никогда не блокируются.
- Повторы: только при достоверно неисполненной попытке (например, отказ соединения **до передачи запроса** либо HTTP 429 по Retry-After). Не более 2 повторных попыток на канал, с ограниченным интервалом. При сетевом таймауте **после возможной передачи** и неизвестном результате — статус «Не удалось подтвердить отправку» (`UNKNOWN`), **никакого автоматического повтора**, чтобы не создавать дубль.
- Запись подтверждённого результата канала происходит сразу после получения ответа. При отказе другого адресата подтверждённый канал больше не отправляется в этом сеансе.
- Ошибки 400/401/403/404, некорректные токены/вебхуки и отсутствие прав — без автоматического повтора; понятное описание на выбранном языке.
- Если эфир остановлен во время `SENDING`, уже отправленные сообщения нельзя отозвать; ещё не начатые запросы отменить, выполняющиеся попытаться остановить, вывести честный частичный результат.
- Гарантия «не более одного подтверждённого сообщения на канал за сеанс» — **best effort**: внешние API не предоставляют нам полноценную универсальную идемпотентность на сетевом уровне. Не обещать абсолютную защиту от дублирования при потере ответа после фактической доставки.

## 8. Кнопки «Тест»

- На «Основном» и «Подключениях» по одной кнопке **«Тест» напротив Telegram** и **«Тест» напротив Discord**. Общей кнопки нет.
- Кнопка отправляет **реальное** сообщение только в выбранный сервис, независимо от остальных, без 60-секундной задержки и только по явному нажатию.
- Текст теста содержит отличимую метку `🧪 Stream Notify — тестовое сообщение / test message`; ссылки могут включаться по текущему шаблону, но содержимое всегда явно тестовое.
- Во время отправки теста кнопка временно блокируется (против двойного нажатия), появляется «Проверяем…», затем достоверный результат, при ошибке — причина.
- Тест не меняет `last_auto_send`, не пересоздаёт эфир, не влияет на таймер и не запускает остальные каналы.

## 9. Автоматическое сохранение настроек

- **Никаких кнопок «Сохранить» или «Применить».** Переключатели, выбор языка, длительности и режимы — сохраняются немедленно.
- Текстовые поля: отложенная запись после **800–1000 мс** без ввода и при потере фокуса; при корректном закрытии OBS или плагина — обязательный сброс ожидающих записей на диск.
- Признак «Сохранено» показывается только после успешного завершения записи; при ошибке — «Не удалось сохранить» без ложной зелёной галочки.
- Конфигурация хранится локально, раздельно от OBS-сцен; рекомендуемое место — данные конфигурации плагина в профиле пользователя OBS. При обновлении версии поддерживается миграция схемы.
- Никаких сетевых запросов из-за сохранения. Секреты отдельно защищаются DPAPI текущего пользователя Windows, а не лежат в открытом JSON.
- При повреждении настройки восстанавливаются из валидной резервной копии либо из безопасных значений по умолчанию **без отправки**; пользователю показывается ошибка и просьба переподключить сервисы.

## 10. Безопасность и приватность

- Telegram-токены и Discord Webhook URL — секреты: маскирование в UI, временный показ по явному действию; Windows DPAPI (пользовательская область), ограничение доступа к файлам профилем Windows.
- Нельзя печатать токены/полные webhook URL в логах, ошибках OBS, отчётах об аварии или диагностике; в диагностике показывать только замаскированные значения.
- Подключения только по HTTPS, проверка сертификатов; запрет перенаправления секретных заголовков/URL на чужие хосты. Проверять допустимый адрес Telegram API и Discord Webhook.
- Передача только в выбранные пользователем Telegram/Discord. **Не передавать** пользовательские ссылки, секреты или события трансляций разработчику плагина, аналитике, рекламным сетям или серверу лицензирования.
- При ошибке DPAPI секрет считается недоступным; не подменять его пустым значением без уведомления и не выполнять рассылку от старого подключения.
- В Discord массовые упоминания отключены по умолчанию; если функция `@everyone` всё-таки включается в 1.0 — только отдельный явный переключатель с предупреждением и учётом прав канала.

## 11. Локализация RU / EN

- Оба языка должны быть **полными** уже в версии 1.0. Все пользовательские строки выносятся в каталог переводов с ключами и подстановками (`{seconds}`, `{service}`).
- Изменение языка применяется без перезапуска OBS и **автоматически сохраняется**.
- Перевод касается состояния `IDLE`, обратного отсчёта, отмены, всех трёх итоговых экранов, ошибок API и справки.
- Шаблон объявления пользователь редактирует самостоятельно: смена языка интерфейса не переписывает пользовательское сообщение.
- Формат времени, множественные формы секунд и длина английских подписей проверяются на узком доке.

## 12. Производительность и надёжность

- Нативный Qt-интерфейс, без Chromium/WebView, без внешнего локального веб-сервера, без `while(true)` и без постоянного опроса OBS/YouTube/Twitch.
- В `IDLE`: **нет периодического таймера обновления UI**, сетевых соединений, фоновой проверки статуса, файловых записей без изменения настроек.
- В `COUNTDOWN`: одно событийное обновление интерфейса раз в 1 секунду, расчёт оставшегося времени по монотонным часам (чтобы задержки UI не смещали срок).
- В `SENDING`: асинхронные сетевые операции с ограниченным числом активных задач, без блокировки Qt/OBS.
- В `SUCCESS` / `PARTIAL` / `FAILED`: один отложенный переход назад; обратный отсчёт возврата обновляется максимум 1 раз в секунду, при необходимости.
- **Целевые метрики для стендовых испытаний, не обещание измеренного результата:** дополнительная CPU-нагрузка в ожидании близка к нулю; среднее <0,1% CPU в простое на эталонном ПК; прирост рабочей памяти <30 МБ; никаких пропусков кадров/звуковых рывков из-за плагина.
- Стабильность: 4-часовой стрим с многократным переключением UI, временным отсутствием сети и открытием/закрытием дока без утечек и аварий OBS. Если метрики не выдержаны — оптимизировать до выпуска.

## 13. Логика отказов и пограничные случаи

| Ситуация | Требуемое поведение |
|---|---|
| Стрим не стартовал (OBS ошибка) | Таймер и рассылка не запускаются |
| Стрим завершён на 30-й секунде | Отмена, ни одного сообщения |
| Пользователь нажал «Отменить» | Нет отправки в текущем эфире; в следующем разрешена |
| Telegram выключен, Discord включён | Отправка только Discord; зелёный успех при подтверждении Discord |
| Telegram успешен, Discord 403 | Telegram ✓, Discord ✕, янтарный экран, повтор Telegram запрещён |
| Оба сервиса отключены | Таймер не запускается, видно предупреждение |
| Сеть недоступна до запроса | Ограниченные повторы; затем честная ошибка |
| Запрос отправлен, ответ пропал | `UNKNOWN`, автоматического повторного сообщения нет |
| OBS переподключился | Новая рассылка не создаётся в том же сеансе |
| OBS открыт посреди эфира | Автоотправка не запускается задним числом |
| Плагин/док закрыли во время таймера | Работа логики сохраняется, пока OBS работает; при выгрузке модуля задачи корректно отменяются |
| Настройки меняются при отсчёте | Для текущего эфира используется снимок на момент старта; новые значения — со следующего |
| Секрет не расшифровался | Мессенджер помечен как не настроенный; не отправлять |
| Один адресат не настроен | Если он включён — предупреждение, другой корректный адресат продолжает работать; общий итог учитывает неудачу включённого |
| OBS выключили до отправки | Отменить отложенную рассылку, безопасно завершить потоки и сохранить настройки |

## 14. Модель данных и структура проекта

### 14.1. Основные настройки (логическая схема)

- `schema_version`: целое, стартовое значение 1.
- `notifications_enabled`: bool, по умолчанию true (но нет отправки без валидных подключений).
- `telegram.enabled`, `telegram.chat_id`, `telegram.secret_ref`.
- `discord.enabled`, `discord.secret_ref`.
- `youtube_url`, `twitch_url`: строки (по умолчанию пусто для публичной сборки — адреса автора **не прошиваются**).
- `message_template`: строка, заводской RU/EN пример; пользовательский текст не заменяется при переключении UI-языка.
- `send_delay_seconds`: enum 60/90/120, по умолчанию 60.
- `result_screen_seconds`: enum 30/45/60, по умолчанию 45.
- `locale`: `auto` / `ru` / `en`; `compact_mode`, `show_obs_notifications`: bool.
- `dock_position`, `dock_visibility`, `first_launch_completed`: состояние интерфейса.
- `event_log`: ограниченный массив без секретов (рекомендуется до 100 последних событий или эквивалентный кольцевой журнал).

### 14.2. Runtime-модель

- `stream_session_id`: локально уникальный идентификатор эфира; `stream_state`: состояние OBS/цикла.
- `session_snapshot`: неизменяемый набор правил текущего эфира.
- `cancelled_for_session`: bool; `per_channel`: `{enabled, status, attempts, confirmed_message_id?, error_code?}`.
- Статусы: `DISABLED`, `NOT_CONFIGURED`, `READY`, `QUEUED`, `SENDING`, `SENT`, `FAILED`, `UNKNOWN`, `CANCELLED`.
- Логика отправки, UI и конфигурация должны быть отдельными компонентами; никакого сохранения UI-состояния непосредственно в сетевом callback.

### 14.3. Предлагаемые компоненты кода

`plugin_entry` (загрузка OBS) → `obs_event_bridge` → `stream_session_controller` → `dispatch_service` → `telegram_client` / `discord_client`; рядом: `settings_store`, `secret_store_dpapi`, `i18n`, `dock_widget`, `event_log`.

## 15. Установка, обновление и удаление

- Установщик проверяет наличие совместимой OBS x64, копирует модуль и ресурсы (переводы/иконки) в корректную структуру плагина; не меняет настройки OBS и не добавляет автозагрузку Windows.
- Первый запуск — док появляется автоматически; в меню «Док-панели» OBS доступно штатное включение/скрытие.
- Обновление поверх старой версии **сохраняет** настройки, выбранный язык, скрытые секреты, шаблон и положение дока; миграция конфигурации проверяется.
- Удаление убирает программные файлы. Пользовательские настройки и секреты удаляются по отдельному явному выбору в деинсталляторе, чтобы случайно не потерять подключения.
- Нужны README RU/EN, инструкция настройки Telegram с `@BotFather`, инструкция Discord Webhook, раздел часто встречающихся ошибок, контакт поддержки и чейнджлог.

## 17. Порядок разработки и артефакты

**Этап 1 — каркас:** исходный проект на базе официального OBS Plugin Template, регистрация нативного дока, появление после установки, сохранение положения, CI-сборка Windows.

**Этап 2 — настройки и оформление:** три подстраницы, RU/EN, независимые переключатели, DPAPI, автосохранение, компактная адаптация, локальный журнал.

**Этап 3 — событие и машина состояний:** OBS start/stop, снимок настроек, отсчёт 60/90/120, отмена, отображение итогов 30/45/60.

**Этап 4 — интеграции:** Telegram API, Discord webhook с подтверждением, тесты, раздельный учёт, ограниченные повторы и обработка неизвестного результата.

**Этап 5 — релиз:** прогоны A01–A24, испытания OBS/Windows, установщик, RU/EN документация, исправление дефектов, `v1.0.0`.

Разработчик должен передать: исходники и файлы сборки, собранную DLL, установщик и деинсталлятор, переводы, документацию, журнал версий, инструкции повторяемой сборки, отчёт о тестировании A01–A24. Прототипы являются **визуальными ориентирами**, но текстовые правила этого ТЗ имеют приоритет при расхождениях.

## 18. Коммерческая и правовая модель

Планируемая цена готового удобного Windows-установщика — **49 ₽, один раз, бессрочное использование**, без постоянной проверки лицензии и серверной активации. Платёжный провайдер и экономика микроплатежей выбираются отдельно; **монетизация не должна блокировать работу уже установленного плагина**.

Нативный плагин OBS, связанный с GPL-компонентами, нужно выпускать с соблюдением условий соответствующей лицензии, включая предоставление исходного кода получателям и свободы его дальнейшего распространения. Это не запрещает платный установщик, но исключает обещание технически запретить бесплатные копии. Окончательный текст лицензии и комплект сторонних лицензий проверяются перед публикацией.

## 19. Открытые инженерные решения до реализации

1. Конкретные поддерживаемые минорные версии OBS и Windows — определить по результатам тестов сборки, не выдавать неподтверждённую совместимость.
2. Порядок восстановления дока после штатного и аварийного закрытия OBS — реализовать с использованием поддерживаемых механизмов OBS/Qt и протестировать на реальных сборках.
3. Сетевая библиотека Qt Network либо другая совместимая без дополнительных тяжёлых зависимостей — выбрать на прототипе.
4. Критерий безопасного повторного запроса после разрыва связи — по реальным API/классам ошибок; неизвестные результаты не ретраить автоматически.
5. Значение «активен» в шапке отличать от «стрим идёт»: плагин может быть активен, когда OBS не вещает.
