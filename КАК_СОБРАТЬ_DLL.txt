# Stream Notify — тестовая Windows DLL через GitHub Actions

**Статус:** подготовлен проект для попытки автоматической компиляции, но успешная сборка ещё не подтверждена. Этот ZIP **не содержит DLL или установщик**. При ошибках компиляции потребуется журнал GitHub Actions. Не вводите реальные токены в репозиторий.

## Для чего нужен этот пакет

Это **наложение на официальный OBS Plugin Template**, а не автономный архив, потому что шаблон содержит свои сборочные скрипты и CMake-модули. Не заменяйте папки `cmake/` и `.github/actions/` шаблона.

## Как получить DLL без Visual Studio

1. Откройте https://github.com/obsproject/obs-plugintemplate и выберите **Use this template → Create a new repository**. Лучше сделать репозиторий **Private**, пока код и плагины проходят тестирование.
2. В новом репозитории выберите **Add file → Upload files**. Распакуйте этот архив, перетащите его **содержимое с сохранением подпапок**: `src/`, `docs/`, `tests/`, `.github/workflows/build-test-windows.yml`, `CMakeLists.txt`, `buildspec.json`, `README_DONATIONS_RU.md`. Подтвердите замену шаблонного `CMakeLists.txt` и `buildspec.json`, если GitHub предложит.
3. В GitHub откройте **Actions → Build Stream Notify test DLL (Windows) → Run workflow**. При первой попытке GitHub может попросить включить Actions.
4. Если сборка стала зелёной, откройте её страницу, блок **Artifacts** → `StreamNotify-Test-DLL-Windows-x64`. Скачайте архив. Внутри должна быть `stream-notify.dll` (и, возможно, `Qt6WebSockets.dll`).
5. Если сборка стала красной — скачайте или скопируйте лог первого упавшего шага **Build using OBS official template toolchain**. По нему исправляются ошибки кода/зависимостей; само по себе получение DLL пока НЕ гарантировано.

## Безопасный тест в OBS

1. Закройте OBS полностью, в том числе в области уведомлений Windows.
2. Создайте папку:
   `C:\ProgramData\obs-studio\plugins\stream-notify\bin\64bit\`
3. Скопируйте в неё `stream-notify.dll`. Если в архиве есть `Qt6WebSockets.dll`, положите его рядом (требует проверок совместимости с используемой сборкой Qt OBS).
4. Создайте папку:
   `C:\ProgramData\obs-studio\plugins\stream-notify\data\locale\`
   (для будущих ресурсных файлов; нынешний UI локализован в исходниках).
5. Запустите OBS и найдите док в меню **Доки** (название может отличаться в локализации) → `Stream Notify`. Если панели нет, выберите **Справка → Файлы журнала → Просмотреть текущий журнал** и найдите `stream-notify` или `Failed to load`.
6. Первый тест проводите без прямого эфира и настоящих токенов: появление панели, смена языка, настройки, закрытие/открытие OBS. Затем — тестовые Telegram/Discord, после — закрытый/непубличный тест стрима; донаты только после отдельной проверки API.

**Если OBS перестаёт запускаться:** закройте OBS и удалите `C:\ProgramData\obs-studio\plugins\stream-notify\` — это отключит тестовый модуль. Сохранённые настройки пользователя OBS останутся отдельно.

## Важно

- Компиляция **не равна** полноценной проверке работы в OBS.
- `Qt6WebSockets` может отсутствовать в стандартном наборе Qt OBS; в этом случае этап CMake завершится с ошибкой, и зависимость придётся добавить отдельно или изменить адаптер.
- Шаблон из GitHub со временем меняется; этот overlay ориентирован на проверенную структуру шаблона с Visual Studio 2022 и OBS/Qt dev-зависимостями.
- Для OBS версии >=30 требуется Windows x64; сборка может потребовать уточнения ABI для конкретной версии OBS.
- До выпуска публичной версии тестировать DonationAlerts/DonatePay следует только на тестовых/своих аккаунтах.
